# Implementing a SmallRye Reactive Messaging Connector

A connector is a CDI-managed bean that bridges reactive messaging channels to an external messaging system.
This guide details the architecture, patterns, and pitfalls learned from building connectors for Kafka, RabbitMQ, Pulsar, AMQP, and others.

Before implementing, study the connector contributing guide at `documentation/src/main/docs/concepts/contributing-connectors.md` and reference existing connectors (Kafka, RabbitMQ, Pulsar) for established patterns.

## 2. Connector Class

The connector is an `@ApplicationScoped` bean annotated with `@Connector("connector-name")`, implementing `InboundConnector`, `OutboundConnector`, and `HealthReporter`.

### 2.1 Configuration Attributes

Declare with `@ConnectorAttribute` on the connector class. The annotation processor generates typed configuration classes (`*ConnectorIncomingConfiguration`, `*ConnectorOutgoingConfiguration`) and markdown documentation in `META-INF/connector/`.

Common attributes every connector needs:
```java
// Connection
@ConnectorAttribute(name = "host", type = "string", direction = INCOMING_AND_OUTGOING, defaultValue = "localhost")
@ConnectorAttribute(name = "port", type = "int", direction = INCOMING_AND_OUTGOING, defaultValue = "5672")
@ConnectorAttribute(name = "username", type = "string", direction = INCOMING_AND_OUTGOING, defaultValue = "guest")
@ConnectorAttribute(name = "password", type = "string", direction = INCOMING_AND_OUTGOING, defaultValue = "guest")
@ConnectorAttribute(name = "ssl", type = "boolean", direction = INCOMING_AND_OUTGOING, defaultValue = "false")

// Incoming
@ConnectorAttribute(name = "failure-strategy", type = "string", direction = INCOMING, defaultValue = "fail")
@ConnectorAttribute(name = "broadcast", type = "boolean", direction = INCOMING, defaultValue = "false")

// Outgoing
@ConnectorAttribute(name = "max-inflight-messages", type = "long", direction = OUTGOING, defaultValue = "1024")
@ConnectorAttribute(name = "wait-for-write-completion", type = "boolean", direction = OUTGOING, defaultValue = "true")

// Observability
@ConnectorAttribute(name = "tracing-enabled", type = "boolean", direction = INCOMING_AND_OUTGOING, defaultValue = "true")
@ConnectorAttribute(name = "health-enabled", type = "boolean", direction = INCOMING_AND_OUTGOING, defaultValue = "true")

// Lifecycle
@ConnectorAttribute(name = "lazy-client", type = "boolean", direction = INCOMING_AND_OUTGOING, defaultValue = "false")
```

### 2.2 CDI Injections

```java
// Core — every connector needs these
@Inject ExecutionHolder executionHolder;                                    // Vert.x instance
@Inject Instance<OpenTelemetry> openTelemetryInstance;                     // OpenTelemetry (for tracing)

// Ack/Failure strategies — pluggable via CDI @Identifier lookup
@Inject @Any Instance<MyAckHandler.Factory> ackHandlerFactories;           // Pluggable ack strategies
@Inject @Any Instance<MyFailureHandler.Factory> failureHandlerFactories;   // Pluggable failure strategies

// Client customization — lets applications modify client builders
@Inject @Any Instance<ClientCustomizer<MyClientConfig>> configCustomizers; // Client config customization

// Optional — depends on connector needs
@Inject Instance<JsonMapping> jsonMapping;                                 // JSON serde (provided by runtime)
@Inject @Any Instance<Map<String, ?>> configMaps;                          // Injectable default config beans via @Identifier
```

`ClientCustomizer<T>` lets applications modify client configuration programmatically. Apply via `ConfigUtils.customize(channelConfig, customizers, config)` before building the client. The type parameter `T` depends on the client — Kafka uses `Map<String, Object>`, RabbitMQ uses `ConnectionFactory`, etc.

### 2.3 Wiring Channels — getPublisher / getSubscriber

The connector creates channel instances, passes all dependencies, and tracks them for health and cleanup:

```java
List<MyIncomingChannel> incomingChannels = new CopyOnWriteArrayList<>();
List<MyOutgoingChannel> outgoingChannels = new CopyOnWriteArrayList<>();

@Override
public Flow.Publisher<? extends Message<?>> getPublisher(Config config) {
    MyConnectorIncomingConfiguration ic = new MyConnectorIncomingConfiguration(config);
    MyClient client = getOrCreateClient(config);
    MyIncomingChannel channel = new MyIncomingChannel(vertx, client, ic,
            config, consCustomizers, failureHandlerFactories);
    incomingChannels.add(channel);
    return channel.getPublisher();
}

@Override
public Flow.Subscriber<? extends Message<?>> getSubscriber(Config config) {
    MyConnectorOutgoingConfiguration oc = new MyConnectorOutgoingConfiguration(config);
    MyClient client = getOrCreateClient(config);
    MyOutgoingChannel channel = new MyOutgoingChannel(client, oc,
            config, jsonMapping, prodCustomizers);
    outgoingChannels.add(channel);
    return channel.getSubscriber();
}
```

### 2.4 Connection/Client Management

Most messaging clients have expensive connection objects (TCP, authentication, thread pools).

**Sharing across channels** — use fingerprinting:
```java
Map<String, MyClient> clients = new ConcurrentHashMap<>();

MyClient getOrCreateClient(Config config) {
    MyConnectorCommonConfiguration common = new MyConnectorCommonConfiguration(config);
    String fingerprint = computeFingerprint(common); // SHA-256 of host:port:user:pass:vhost:ssl
    return clients.computeIfAbsent(fingerprint, key -> {
        MyClientBuilder builder = MyClient.builder()
            .host(common.getHost()).port(common.getPort())
            .username(common.getUsername()).password(common.getPassword());
        if (common.getSsl()) { builder.tls(); }
        builder = ConfigUtils.customize(config, connCustomizers, builder);
        return builder.build();
    });
}
```

Existing patterns: ref-counting (RabbitMQ AMQP), per-channel clients (Kafka), shared resources (Pulsar).

- **Recovery**: delegate reconnection to the client library.
- **Lazy init**: use `lazy-client` attribute with memoized Uni for producers.

### 2.5 Lifecycle

```java
@PostConstruct
void init() { this.vertx = executionHolder.vertx(); }

public void terminate(
        @Observes(notifyObserver = Reception.IF_EXISTS)
        @Priority(50) @BeforeDestroyed(ApplicationScoped.class) Object event) {
    incomingChannels.forEach(MyIncomingChannel::close);
    outgoingChannels.forEach(MyOutgoingChannel::close);
    clients.values().forEach(c -> { try { c.close(); } catch (Exception e) {} });
}
```

Close channels first, then clients. Wrap each close in try/catch.

## 3. Incoming Channel

The incoming channel bridges the client's consumption model to a `Flow.Publisher<? extends Message<?>>`.

### 3.1 Push-based Sources (callback-driven)

**Unicast** (single subscriber, default):
```java
Multi.createFrom().<Message<?>>emitter(emitter -> {
    setupConsumer(client, config,
        msg -> { if (!emitter.isCancelled()) emitter.emit(msg); },
        err -> { if (!emitter.isCancelled()) emitter.fail(err); },
        ()  -> { if (!emitter.isCancelled()) emitter.complete(); });
    emitter.onTermination(this::close);
}, BackPressureStrategy.BUFFER);
```

**Broadcast** (multiple subscribers):
```java
BroadcastProcessor<Message<?>> processor = BroadcastProcessor.create();
setupConsumer(client, config, processor::onNext, processor::onError, processor::onComplete);
```

`BroadcastProcessor` has no buffer — messages dropped if no subscriber. Choose based on `broadcast` config attribute.

### 3.2 Pull-based Sources

```java
Multi.createBy().repeating()
    .completionStage(consumer::receiveAsync)
    .until(m -> closed.get())
    .emitOn(command -> context.runOnContext(event -> command.run()))
    .onItem().transform(raw -> createMessage(raw))
```

For full control (Kafka), implement `AbstractMulti` + `Flow.Subscription` with internal queue and pause/resume.

### 3.3 Consumer Configuration Pattern

Break setup into focused methods:
```java
private void setupConsumer(MyClient client, MyConfig config, ...) {
    MyConsumerBuilder builder = client.consumerBuilder()
        .destination(config.getDestination().orElse(this.channel));
    configureStartPosition(builder, config);  // first, last, next, offset:N, timestamp:T
    configureTracking(builder, config);
    configureFiltering(builder, config);
    builder = ConfigUtils.customize(channelConfig, consumerCustomizers, builder);
    this.consumer = builder.build();
}
```

### 3.4 Vert.x Context and Threading

Create a dedicated event loop context per channel and dispatch message creation to it:
```java
this.context = Context.newInstance(((VertxInternal) vertx.getDelegate()).createEventLoopContext());

// In client callback:
context.runOnContext(() -> {
    MyMessage msg = new MyMessage(rawMessage, ackHandler, failureHandler);
    // msg now has LocalContextMetadata from this Vert.x context
    onMessage.accept(msg);
});
```

### 3.5 Backpressure

Bridge the client's native backpressure to reactive streams:
- **Credit-based**: release credits in ack handler
- **Pause/resume** (Kafka): pause polling when queue full
- **Prefetch/QoS** (AMQP): configure prefetch count
- **Demand-driven** (Pulsar): one-at-a-time async receive

## 4. Message Implementation

### 4.1 Incoming Message

**CRITICAL**: Implement `getAckWithMetadata()` and `getNackWithMetadata()`. Without these, POST_PROCESSING ack chain silently fails in `@Incoming -> @Outgoing` passthrough, stalling the pipeline at scale.

```java
public class MyIncomingMessage implements ContextAwareMessage<T>, MetadataInjectableMessage<T> {
    private Metadata metadata;
    private final MyIncomingMetadata connectorMetadata;
    private final AckHandler ackHandler;
    private final FailureHandler failureHandler;

    public MyIncomingMessage(RawMessage raw, AckHandler ack, FailureHandler fail) {
        this.connectorMetadata = new MyIncomingMetadata(raw);
        this.ackHandler = ack;
        this.failureHandler = fail;
        this.metadata = ContextAwareMessage.captureContextMetadata(connectorMetadata);
    }

    @Override public T getPayload() { return connectorMetadata.getBody(); }
    @Override public Metadata getMetadata() { return metadata; }

    // CRITICAL: Enable POST_PROCESSING ack chaining
    @Override public Function<Metadata, CompletionStage<Void>> getAckWithMetadata() { return this::ack; }
    @Override public BiFunction<Throwable, Metadata, CompletionStage<Void>> getNackWithMetadata() { return this::nack; }

    @Override public CompletionStage<Void> ack(Metadata m) {
        return ackHandler.handle(this).subscribeAsCompletionStage();
    }
    @Override public CompletionStage<Void> nack(Throwable reason, Metadata m) {
        return failureHandler.handle(this, reason).subscribeAsCompletionStage();
    }
    @Override public void injectMetadata(Object o) { this.metadata = this.metadata.with(o); }
}
```

### 4.2 Incoming Metadata

Expose client message properties:
```java
public class MyIncomingMetadata {
    private final RawMessage rawMessage;
    public long getOffset() { ... }
    public String getKey() { ... }
    public Map<String, Object> getHeaders() { ... }
    public RawMessage getRawMessage() { return rawMessage; }
}
```

### 4.3 Outgoing Metadata

Builder pattern for setting outgoing message properties:
```java
public class MyOutgoingMetadata {
    public static Builder builder() { return new Builder(); }
    public static class Builder {
        public Builder withKey(String key) { ... return this; }
        public Builder withHeader(String k, Object v) { ... return this; }
        public MyOutgoingMetadata build() { return new MyOutgoingMetadata(this); }
    }
}
// Usage: Message.of(payload).addMetadata(MyOutgoingMetadata.builder().withKey("k").build())
```

## 5. Acknowledgment and Failure Strategies

### 5.1 Ack Handler

```java
public interface AckHandler {
    Uni<Void> handle(MyIncomingMessage message);
    default void terminate() {}
}
```

The handler performs the client-side ack, then returns on the message context:
```java
// Fire-and-forget ack
client.acknowledge(message.getId());
return Uni.createFrom().voidItem().emitOn(message::runOnMessageContext);

// Async ack
return Uni.createFrom().completionStage(client.commitAsync(message.getOffset()))
    .emitOn(message::runOnMessageContext);
```

Create handlers as `final` fields **before** the consumer starts. Common strategies: latest (per-message), throttled (batched via Vert.x timer), auto (client-managed), ignore.

### 5.2 Failure Handler — CDI Factory Pattern

Each strategy is a discoverable CDI bean:
```java
public interface FailureHandler {
    interface Factory {
        FailureHandler create(String channel, MyConfig config, Object clientContext);
    }
    Uni<Void> handle(MyIncomingMessage message, Throwable reason);
    default void terminate() {}
}

@ApplicationScoped @Identifier("fail")
public static class Factory implements FailureHandler.Factory { ... }
```

Channel resolves: `failureHandlerFactories.select(Identifier.Literal.of(strategy)).get().create(...)`.

### 5.3 Dead Letter Queue

Following the Kafka `KafkaDeadLetterQueue` pattern:
1. Factory is a CDI bean injecting `JsonMapping`, `ClientCustomizer`, `SubscriberDecorator`
2. Derive config via `Configs.prefixOverride(config.config(), suffix, overrides)`
3. Create internal outgoing channel with derived config
4. Wire `UnicastProcessor` via `Wiring.wireOutgoingConnectorToUpstream(processor, channel.getSubscriber(), subscriberDecorators, channelName, config)`
5. In `handle()`: create DL message with failure metadata, chain ack to original, push to processor

## 6. Outgoing Channel

### 6.1 Producer Lifecycle — Memoized Uni

```java
this.producerUni = Uni.createFrom().item(() -> {
    MyProducer p = builder.build();
    this.producer = p;
    return p;
}).memoize().indefinitely();

if (!config.getLazyClient()) { producerUni.await().indefinitely(); }
```

### 6.2 SenderProcessor

```java
SenderProcessor processor = new SenderProcessor(maxInflight, waitForCompletion, this::publishMessage);
this.subscriber = MultiUtils.via(processor, m -> m.onFailure().invoke(t -> log.error(channel, t)));
```

### 6.3 Publish Message Pattern

```java
private Uni<Void> publishMessage(Message<?> message) {
    return producerUni
        .onItem().transform(p -> buildClientMessage(p, message))
        .onItem().transformToUni(clientMsg -> sendToClient(clientMsg))
        .onItemOrFailure().transformToUni((result, t) -> {
            if (t == null) {
                OutgoingMessageMetadata.setResultOnMessage(message, result);
                return Uni.createFrom().completionStage(message.ack());
            } else {
                return Uni.createFrom().completionStage(message.nack(t));
            }
        });
}
```

### 6.4 Bridging Async Send to Uni

```java
// Callback-based
private Uni<SendResult> sendToClient(ClientMessage msg) {
    return Uni.createFrom().emitter(emitter -> {
        producer.send(msg, result -> {
            if (result.isSuccess()) emitter.complete(result);
            else emitter.fail(new Exception("Send failed: " + result.getError()));
        });
    });
}

// CompletionStage-based
private Uni<SendResult> sendToClient(ClientMessage msg) {
    return Uni.createFrom().completionStage(() -> producer.sendAsync(msg));
}
```

### 6.5 Payload Handling

```java
private ClientMessage buildClientMessage(MyProducer p, Message<?> message) {
    Object payload = message.getPayload();
    if (payload instanceof ClientMessage clientMsg) return clientMsg;           // passthrough
    if (payload instanceof MyOutgoingMessage outgoing)                          // wrapper type
        return outgoing.build(p.messageBuilder(), serialize(outgoing.getPayload()));

    ClientMessageBuilder builder = p.messageBuilder();
    builder.body(serialize(payload));
    message.getMetadata(MyOutgoingMetadata.class).ifPresent(meta -> { ... });
    return builder.build();
}

byte[] serialize(Object payload) {
    if (payload instanceof byte[] bytes) return bytes;
    if (payload instanceof String s) return s.getBytes(UTF_8);
    if (jsonMapping.isResolvable()) return jsonMapping.get().toJson(payload).getBytes(UTF_8);
    return payload.toString().getBytes(UTF_8);
}
```

### 6.6 Connector-Specific Outgoing Message Type

Gives users access to the client's message builder:
```java
public class MyOutgoingMessage {
    public static MyOutgoingMessage of(UnaryOperator<ClientMessageBuilder> customizer) { ... }
    public static MyOutgoingMessage of(Object payload, UnaryOperator<ClientMessageBuilder> customizer) { ... }
}

// Usage:
@Outgoing("sink")
Multi<MyOutgoingMessage> produce() {
    return Multi.createFrom().items(
        MyOutgoingMessage.of(myPojo, builder -> builder.header("type", "order").key("k")));
}
```

## 7. Advanced Patterns

### 7.1 Batch Consumption

Controlled by a `batch` config attribute:
```java
if (config.getBatch()) {
    Multi<Message<?>> batchStream = Multi.createBy().repeating()
        .completionStage(consumer::batchReceiveAsync)
        .until(m -> closed.get())
        .filter(batch -> batch.size() > 0)
        .onItem().transform(batch -> new MyBatchMessage<>(batch, ackHandler, failureHandler));
}
```
See `IncomingKafkaRecordBatch` and `PulsarIncomingBatchMessage` for reference.

### 7.2 Topology / Resource Declaration

```java
if (config.getDeclareDestination()) {
    client.createDestination(config.getDestination(), config.getDurable(), config.getAutoDelete());
}
```
Make optional via config (`declare=true` default) for production environments with pre-provisioned infrastructure.

### 7.3 CDI-Provided Strategy Customization

Inject `Instance<T>` with `@Any`, resolve by `@Identifier`:
```java
@Inject @Any Instance<MyStrategy> strategies;
MyStrategy strategy = CDIUtils.getInstanceById(strategies, channelName, () -> defaultStrategy);
```

Used for: ack/failure strategies, config beans (`Map<String, Object>`), deserialization handlers, rebalance listeners, request customizers, credentials providers.

### 7.4 Custom Emitter Types

For transactions and request-reply — extends `@Inject @Channel Emitter<T>`:

1. **Interface** extending `EmitterType`
2. **Implementation** implementing `MessagePublisherProvider`
3. **Factory** as `@ApplicationScoped @EmitterFactoryFor(MyTransactions.class)`

```java
@ApplicationScoped @EmitterFactoryFor(MyTransactions.class)
public class MyTransactionsFactory implements EmitterFactory<MyTransactionsImpl<Object>> {
    public MyTransactionsImpl<Object> createEmitter(EmitterConfiguration config, long bufferSize) { ... }
    public MessagePublisherProvider<?> createEmitter(EmitterConfiguration config, long bufferSize, Config channelConfig) {
        if (!EmitterFactory.isConnector(channelConfig, CONNECTOR_NAME)) return createEmitter(config, bufferSize);
        return new MyTransactionsImpl<>(config, channelConfig);
    }
}
// Usage: @Inject @Channel("orders") MyTransactions<Order> tx;
```

Used by: Kafka (transactions, request-reply), Pulsar (transactions), RabbitMQ (request-reply).

## 8. Cross-Cutting Concerns

### 8.1 Message Converters

`@ApplicationScoped` CDI beans implementing `MessageConverter`:
```java
public boolean canConvert(Message<?> in, Type target) {
    return String.class.equals(target) && in.getMetadata(MyMetadata.class).isPresent();
}
public Message<?> convert(Message<?> in, Type target) { return in.withPayload(...); }
```
Standard set: `String`, `JsonObject`/`JsonArray`, raw client message, POJO via `JsonMapping` (priority `MAX_VALUE`).

### 8.2 OpenTelemetry Tracing

1. Trace carrier type + `TextMapGetter`/`TextMapSetter`
2. `AttributesExtractor` with `MessagingAttributesGetter` (all abstract methods)

`HealthReporter` on connector: `getReadiness()`, `getLiveness()`, `getStartup()` — delegate to channel-level health.

## 9. Testing

### 9.1 Infrastructure
- **JUnit 5 extension** for container lifecycle (singleton via global store)
- **`WeldTestBase`** registers all CDI beans: connector, converters, ack/failure handler factories, decorators
- **`MapBasedConfig`** + `SmallRyeConfigTestUtil` for programmatic configuration

### 9.2 Required Test Coverage
1. Incoming messages + metadata
2. Outgoing messages + metadata
3. All ack strategies
4. All failure strategies (fail, ignore, DLQ)
5. Context propagation (`LocalContextMetadata`)
6. Health checks
7. Message converters (all types)
8. Tracing (in/out/disabled)
9. Backpressure / flow control
10. Throughput at scale (incoming, outgoing, **end-to-end `byte[] process(byte[])`**)
11. Client customizers
12. Serde (JSON, POJO, raw)
13. Position/offset resume
14. Dead letter queue

### 9.3 Key Pitfalls
- Wait for broker confirmations before consuming
- Fresh client instances after container restart
- Publish AFTER app starts for broadcast tests
- Register ALL CDI beans in `WeldTestBase`
- Always test `byte[] process(byte[])` passthrough at scale — exercises POST_PROCESSING ack chain

## 10. Critical Pitfalls

1. **Missing `getAckWithMetadata()`/`getNackWithMetadata()`** — POST_PROCESSING ack chain silently breaks, pipeline stalls at scale. Most insidious bug.

2. **BroadcastProcessor has no buffer** — Use emitter for unicast, BroadcastProcessor only for broadcast.

3. **Handler init before consumer** — Consumer delivers immediately after `build()`. Use `final` handler fields.

4. **`emitOn(message::runOnMessageContext)` in ack handlers** — Part of the contract. Don't remove.

5. **Ack chain threading** — Handler called on client I/O thread. Must be thread-safe.

6. **Connection cleanup order** — Channels first, then clients. Try/catch each close.

7. **Async bridging** — `Uni.createFrom().emitter()` for callbacks, `completionStage()` for futures. Never block.
