## Project Overview

SmallRye Reactive Messaging is an implementation of the Eclipse MicroProfile Reactive Messaging specification.
It provides a CDI-based framework for building event-driven microservices with multiple messaging connectors (Kafka, AMQP, MQTT, RabbitMQ, Pulsar, JMS, Camel, GCP Pub/Sub, AWS SNS/SQS).

Built on **Mutiny** (reactive library) and **Vert.x** (async I/O). Java 17 minimum.

## Build Commands

```bash
# Fast build (skips tests, revapi, BOM generation)
mvn clean install -Dquickly

# Full build with tests
mvn clean install

# Build without tests
mvn clean install -DskipTests

# Run tests for a specific module
mvn verify -pl :smallrye-reactive-messaging-kafka

# Run a single test class
mvn test -pl :smallrye-reactive-messaging-provider -Dtest=PausableChannelTest

# Run a single test method
mvn test -pl :smallrye-reactive-messaging-provider -Dtest=PausableChannelTest#testPause

# Skip API compatibility checks (RevAPI)
mvn verify -Drevapi.skip=true

# Skip formatting checks
mvn verify -Dformat.skip=true

# Build with coverage
mvn verify -Pcoverage
```

Connector integration tests require a container runtime (Docker or Podman) via Testcontainers.

## Architecture

### Core Abstractions

- **Message\<T\>** - Envelope carrying payload, metadata, and ack/nack functions
- **Channel** - Named conduit for messages, configured via MicroProfile Config
- **Connector** - Bridges channels to external messaging systems (`InboundConnector` / `OutboundConnector`)
- **Mediator** - CDI bean methods annotated with `@Incoming` / `@Outgoing` that process messages
- **Emitter** - Programmatic message injection into channels

### Configuration Pattern

Channels are configured via MicroProfile Config properties:
```
mp.messaging.incoming.{channel-name}.connector={connector-name}
mp.messaging.incoming.{channel-name}.{attribute}={value}
mp.messaging.outgoing.{channel-name}.connector={connector-name}
```

### Key Modules

| Module | Purpose |
|--------|---------|
| `api` | MicroProfile Reactive Messaging API + SmallRye extensions |
| `smallrye-reactive-messaging-provider` | Core CDI extension, mediator wiring, channel management |
| `smallrye-reactive-messaging-kafka` | Kafka connector (largest connector) |
| `smallrye-reactive-messaging-kafka-api` | Kafka-specific API types |
| `smallrye-reactive-messaging-kafka-test-companion` | Kafka test utilities |
| `smallrye-reactive-messaging-otel` | OpenTelemetry tracing integration |
| `smallrye-reactive-messaging-health` | MicroProfile Health integration |
| `smallrye-connector-attribute-processor` | Annotation processor generating connector config docs |
| `test-common` | Shared test utilities (MapBasedConfig, etc.) |

### Wiring Flow

1. `ReactiveMessagingExtension` (CDI extension) discovers `@Incoming`/`@Outgoing` methods at deployment
2. `ConfiguredChannelFactory` creates channels from MicroProfile Config
3. `MediatorManager` wires mediators to channels
4. Connectors create reactive streams (publishers/subscribers) bridging to external systems
5. Messages flow through the reactive pipeline with ack/nack propagation

## Testing Patterns

- **Core tests** extend `WeldTestBaseWithoutTails` (Weld SE CDI container)
  - Use `addBeanClass()` to register beans, `initialize()` to boot, `get()` to retrieve instances
- **Connector tests** use Testcontainers for real broker instances (Kafka, RabbitMQ, Pulsar, etc.)
- **In-memory connector** (`smallrye-reactive-messaging-in-memory`) for lightweight testing without brokers
- **MapBasedConfig** (in `test-common`) for programmatic test configuration
- Assertions: AssertJ. Async: Awaitility. Mocking: Mockito.

## Editing Rules

- **Preserve existing comments.** When editing a section of code, keep all
  existing comments that are not directly invalidated by your change. Never
  drop comments from code you are not modifying.
- **Never manually sort or reorder imports** — `impsort-maven-plugin` handles
  import ordering automatically. Just add imports where needed; do not make
  edits whose sole purpose is reorganizing imports.

## Git Instructions

- Run `mvn clean install -DskipTests` before committing to apply automatic formatting
- Never add yourself to the list of commit co-authors
- Never mention yourself in commit messages in any way (no "Generated by", no AI tool links, etc.)

## Code Style

- 4-space indentation (2 for XML), UTF-8, LF line endings (see `.editorconfig`)
- Formatting is enforced automatically during build (inherited from `smallrye-parent`):
  - `formatter-maven-plugin` — Java source formatting (Eclipse format rules from `smallrye-code-rules`).
  Run `mvn process-sources` to auto-format without a full build.
  - `impsort-maven-plugin` — import sorting (groups: `java., javax., jakarta., org., com.`), removes unused imports
  - Skip with `-Dformat.skip=true`
- Use **JBoss Logging** (`@MessageLogger` annotation processor) for production code
- Connector config attributes: annotate with `@ConnectorAttributes` and use `smallrye-connector-attribute-processor`
